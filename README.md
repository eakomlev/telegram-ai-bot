# Telegram AI Summary Bot

Бот для саммари групповых чатов: TypeScript, Node.js 22, grammY, OpenAI API и PostgreSQL 17. Запуск через Docker Compose, получение сообщений через long polling — домен и открытый HTTP-порт не нужны.

## Быстрый запуск

1. Создайте бота в [@BotFather](https://t.me/BotFather) командой `/newbot` и сохраните токен.
2. В BotFather выполните `/setprivacy`, выберите бота и **Disable**. Если бот уже был добавлен в группу, удалите его и добавьте заново. Для надёжной проверки прав пользователей назначьте бота администратором группы.
3. Создайте API-ключ в [OpenAI Platform](https://platform.openai.com/api-keys), подключите оплату API.
4. Подготовьте конфигурацию:

   ```bash
   cp .env.example .env
   ```

   В `.env` заполните `TELEGRAM_BOT_TOKEN`, `OPENAI_API_KEY`, задайте собственный `POSTGRES_PASSWORD`. Не публикуйте `.env` и ключи.
5. Запустите:

   ```bash
   docker compose up -d --build
   docker compose logs -f bot
   ```

6. Добавьте бота в группу, предупредите участников о сохранении сообщений и передаче выбранной переписки в OpenAI. Отправьте несколько обычных сообщений, затем `/summary` от аккаунта администратора.

База и таблицы создаются автоматически; данные сохраняются в Docker volume `postgres_data`. Postgres не публикует порт наружу. Для одной пары токен/бот должен работать только один polling-процесс; старый webhook необходимо удалить перед первым запуском, если он был установлен другим приложением.

## Команды

| Команда | Действие |
| --- | --- |
| `/summary` | Саммари последних 100 сообщений |
| `/summary 500` | Саммари последних 500 сообщений |
| `/summary 24h` | Саммари за последние 24 часа |
| `/summary 7d` | Саммари за последние 7 дней |
| `/help` | Справка |
| `/privacy` | Что сохраняется и отправляется модели |
| `/chatid` | ID группы для ограничения доступа |

Бот выделяет темы, решения, задачи и открытые вопросы. Саммари запрашиваются вручную. По умолчанию запрос доступен только администраторам; сообщения обычных участников также сохраняются. Текст и подписи исходящих ответов бота на @упоминания и автоответы тоже пишутся в Postgres (чтобы следующий контекст их видел; сами изображения не сохраняются); саммари, стихи, GIF, новости и служебные сообщения туда не попадают. Для анонимного администратора запрос нужно отправить от личного аккаунта. Команды и чужие боты исключаются из анализа; сохранённые ответы этого бота не участвуют в `/summary` / `/verse` / `/gif`.

## Автоматическая загрузка коротких видео

Отправьте **только ссылку** отдельным сообщением, например `https://www.youtube.com/shorts/VIDEO_ID`. Бот скачает публичный ролик и ответит видео в той же теме группы. Сообщения с дополнительным текстом, несколькими ссылками и отредактированные сообщения не запускают загрузку.

Поддерживаются YouTube Shorts (также короткие ролики по `youtu.be`), TikTok (включая `vm.tiktok.com` и `vt.tiktok.com`), Instagram Reels и VK Клипы. Другие URL игнорируются. Ссылка очищается от параметров отслеживания.

Видео отправляется **без подписи** (без описания и метаданных), чтобы не тащить рекламу из оригинала. Текст из видео не распознаётся и в OpenAI не отправляется.

В Docker установлены `yt-dlp`, Python, Node.js (для извлечения YouTube), `ffmpeg` и `ffprobe`. Видео приводится к MP4 с H.264/AAC и разрешением до 1080 пикселей по длинной стороне для воспроизведения в Telegram. После успешной отправки Telegram `file_id` сохраняется в Postgres (`VIDEO_CACHE_SIZE`, по умолчанию 1000): повтор той же ссылки отдаётся сразу без скачивания. Файлы временные и удаляются после отправки или ошибки. При остановке процесса активные скачивания прерываются. Внезапное принудительное завершение контейнера может оставить файлы до его пересоздания.

По умолчанию доступна одна параллельная загрузка, длительность до 180 секунд и файл до 45 МБ (ниже лимита облачного Telegram Bot API). Ссылки, отправленные в течение 30 секунд после предыдущей в той же группе, игнорируются; при занятом обработчике бот просит повторить позже. Очереди отложенных заданий нет. Скачивание и отправка ограничены общим таймаутом.

Настройки в `.env`:

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `VIDEO_ENABLED` | `true` | Автоматическая загрузка для участников разрешённых групп |
| `VIDEO_MAX_SIZE_MB` | `45` | Максимальный размер скачанного/отправляемого файла, не больше 45 МБ |
| `VIDEO_MAX_DURATION_SECONDS` | `180` | Максимальная длительность |
| `VIDEO_TIMEOUT_SECONDS` | `180` | Общее время обработки, включая отправку |
| `VIDEO_COOLDOWN_SECONDS` | `30` | Интервал между загрузками группы |
| `VIDEO_MAX_CONCURRENT` | `1` | Число одновременных обработок (1–3) |

Для локальной разработки дополнительно установите `yt-dlp[default]`, `ffmpeg` и `ffprobe` в `PATH`. Без них саммари работает, но загрузка видео завершится ошибкой. Для отключения функции задайте `VIDEO_ENABLED=false`.

Сервисы могут блокировать серверные IP, требовать вход или менять механизм скачивания. Поддержка платформ зависит от yt-dlp; закрытые, удалённые, платные и требующие авторизации публикации не поддерживаются. Cookies и учётные данные сайтов бот не использует. Для обновления извлекателей пересоберите образ: `docker compose build --no-cache bot && docker compose up -d`. При необходимости закрепите проверенную версию: `docker compose build --build-arg YT_DLP_VERSION=ВЕРСИЯ bot`.

Проверка инструментов и преобразования синтетического видео внутри образа (без обращения к соцсетям):

```bash
docker build -t telegram-ai-bot:test .
docker run --rm -v "$PWD/test:/tests:ro" --entrypoint sh telegram-ai-bot:test /tests/media-smoke.sh
```

## Посты с картинками через gallery-dl

Отдельная ссылка на пост Instagram (`/p/...`), X/Twitter (`/user/status/...`), Reddit (`/r/.../comments/...`), Pixiv (`/artworks/...`) или альбом Imgur (`/a/...`, `/gallery/...`) запускает загрузку изображений. Ссылки на товары Wildberries — фотографии и название товара. Ссылки на профили, ленты и произвольные сайты игнорируются. Видео по-прежнему обрабатывает yt-dlp; изображения — gallery-dl.

Одна картинка отправляется как фото, несколько — одним альбомом до 10 изображений в той же теме, ответом на исходное сообщение. Первая картинка содержит доступные метаданные поста: название, автор, дата, описание, лайки и ссылка на оригинал. Подпись сокращается до лимита Telegram. JPEG, PNG, WebP и AVIF приводятся к JPEG размером до 1920 пикселей; у очень узких изображений добавляются поля. Исходные файлы после обработки удаляются. GIF и видео внутри смешанного поста пропускаются; порядок изображений определяется именами файлов загрузчика.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `GALLERY_ENABLED` | `true` | Включить обработку постов с изображениями |
| `GALLERY_MAX_IMAGES` | `10` | Максимум изображений (1–10); загрузчик рассматривает первые N файлов публикации |
| `GALLERY_MAX_IMAGE_MB` | `15` | Максимальный размер исходной картинки |
| `GALLERY_MAX_TOTAL_MB` | `80` | Лимит объёма временных файлов при скачивании; проверяется каждые 0,5 сек. |
| `GALLERY_TIMEOUT_SECONDS` | `180` | Таймаут загрузки, обработки и отправки |
| `MEDIA_MAX_CONCURRENT` | `1` | Общий лимит параллельных заданий видео и картинок |
| `MEDIA_COOLDOWN_SECONDS` | `30` | Общий интервал между загрузками одной группы |

Если `MEDIA_*` не заданы, используются прежние `VIDEO_MAX_CONCURRENT` и `VIDEO_COOLDOWN_SECONDS` для совместимости. Внутри поста видео пропускаются, поэтому картинок может оказаться меньше заданного лимита. Превышение суммарного объёма прерывает обработку. Приватные посты и платформы, требующие входа, по-прежнему часто недоступны.

Для локального запуска дополнительно установите `gallery-dl` в `PATH`. В Docker он устанавливается автоматически. Обновление: `docker compose build --no-cache bot && docker compose up -d`. Чтобы закрепить версию: `docker compose build --build-arg GALLERY_DL_VERSION=ВЕРСИЯ bot`.

## Настройки

Все параметры перечислены в [.env.example](.env.example).

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `OPENAI_MODEL` | `gpt-6-sol` | Модель Chat Completions; для `gpt-6*` бот ставит `reasoning_effort=none` (нужно для tool calling в @упоминаниях) |
| `OPENAI_TIMEOUT_MS` / `OPENAI_MAX_RETRIES` | `90000` / `1` | Таймаут и число повторов OpenAI SDK |
| `OPENAI_BASE_URL` | пусто | Опциональный совместимый endpoint |
| `OPENAI_INPUT_USD_PER_1M_TOKENS` / `OPENAI_OUTPUT_USD_PER_1M_TOKENS` | `2` / `10` | Оценка $ за 1M токенов для `/usage` |
| `OPENAI_IMAGE_USD` | `0.011` | Оценка $ за одну сгенерированную картинку |
| `USAGE_RETENTION_DAYS` | `90` | Срок хранения записей расходов OpenAI |
| `GIPHY_API_KEY` | пусто | Ключ Giphy для `/gif` (без ключа команда недоступна) |
| `GIF_DEFAULT_MESSAGE_COUNT` / `GIF_MAX_MESSAGE_COUNT` | `40` / `80` | Сколько сообщений смотреть для GIF-реакции |
| `NEWS_ENABLED` | `true` | Глобально включить ежедневные новости в группах с настройкой |
| `NEWS_MAX_OUTPUT_TOKENS` / `NEWS_TICK_INTERVAL_MS` / `NEWS_RETRY_MINUTES` | `700` / `60000` / `20` | Лимит ответа, интервал опроса планировщика и мягкий повтор при сбое |
| `AUTO_ANSWER_ENABLED` | `true` | Глобальный переключатель автоответа; в группе всё равно нужно включить в `/settings` (по умолчанию выкл) |
| `AUTO_ANSWER_DELAY_SECONDS` / `AUTO_ANSWER_TICK_INTERVAL_MS` | `300` / `15000` | Сколько ждать ответа людей и как часто опрашивать очередь |
| `AUTO_ANSWER_CONTEXT_MAX_MESSAGES` / `AUTO_ANSWER_CONTEXT_LOOKBACK_MINUTES` / `AUTO_ANSWER_CONTEXT_MAX_CHARS` | `12` / `15` / `2500` | Окно предшествующих сообщений как контекст OpenAI при автоответе (`0` сообщений — только вопрос); пересечение лимитов по числу, времени и символам |
| `MENTION_CONTEXT_MAX_MESSAGES` / `MENTION_CONTEXT_LOOKBACK_MINUTES` / `MENTION_CONTEXT_MAX_CHARS` | `6` / `10` / `500` | Окно сообщений до @упоминания (или до цитаты, если есть reply); `0` — без контекста; ужимается раньше цитаты и запроса в общем лимите `MENTION_MAX_INPUT_CHARS` |
| `ALLOWED_CHAT_IDS` | пусто | Разрешённые группы через запятую, например `-1001234567890,-1009876543210`; пусто — все группы |
| `OWNER_USER_ID` | пусто | Ваш Telegram user id; в личке `/stats` — сводка расходов OpenAI по всем группам только для вас |
| `SUMMARY_ADMIN_ONLY` | `true` | Только администраторы могут тратить API-баланс |
| `DEFAULT_MESSAGE_COUNT` | `100` | Число сообщений без аргумента |
| `MAX_MESSAGE_COUNT` | `1000` | Максимум сообщений в одном запросе, включая выбор по периоду |
| `MAX_INPUT_CHARS` | `60000` | Максимум символов JSON переписки в запросе; это не число токенов |
| `MAX_OUTPUT_TOKENS` | `1500` | Лимит длины ответа модели |
| `SUMMARY_COOLDOWN_SECONDS` | `60` | Минимальный интервал между запросами одной группы |
| `RETENTION_DAYS` | `30` | Срок хранения сообщений |
| `RETENTION_CLEANUP_INTERVAL_MS` | `3600000` | Интервал фоновой очистки |
| `PG_POOL_MAX` / `PG_*_TIMEOUT_MS` | см. `.env.example` | Пул и таймауты Postgres |
| `VIDEO_MAX_HEIGHT` / `VIDEO_FFMPEG_*` | `1080` / см. пример | Качество перекодирования видео |
| `VIDEO_CACHE_SIZE` | `1000` | Сколько последних роликов помнить по `file_id` (0 — выключить) |
| `GALLERY_MAX_DIMENSION` / `GALLERY_OUTPUT_MAX_MB` | `1920` / `10` | Размер JPEG для Telegram |

При превышении объёма выбираются самые свежие сообщения, бот указывает ограничение в ответе. Если самое свежее сообщение само превышает лимит, оно обрезается. Выборка идёт по всей группе, включая темы форума. Расходы зависят от объёма и модели; лимит частоты не заменяет общий денежный бюджет. Повторные запросы оплачиваются заново. Неуспешный запрос также занимает интервал ожидания.

Чтобы ограничить доступ одной группой: вызовите `/chatid`, внесите результат в `ALLOWED_CHAT_IDS` и пересоздайте контейнер `docker compose up -d`. Неизвестные группы будут игнорироваться.

## Данные и ограничения Telegram

- Сохраняются текст и подписи участников, а также текст и подписи исходящих ответов бота на @упоминания и автоответы (сами изображения не сохраняются); плюс отображаемое имя автора, время, ID группы и сообщения, а также ID темы форума (`message_thread_id`), если есть. Саммари, стихи, GIF, новости и служебные сообщения бота в историю для контекста не пишутся. Содержимое файлов, фото, аудио и видео не анализируется.
- Сообщения до подключения бота недоступны. Telegram не гарантирует получение обновлений при простое бота дольше 24 часов.
- Редактирование обновляет сохранённый текст, если Telegram прислал обновление. Удаления сообщений обычных групп Bot API не сообщает, поэтому удалённый текст может остаться в базе до истечения срока хранения.
- Модель получает выбранные сообщения и имена авторов. Политики хранения у OpenAI действуют отдельно от локального `RETENTION_DAYS`. Не используйте бот для данных, которые нельзя отправлять в облако.
- Вывод модели может содержать ошибки: важные решения и задачи нужно сверять с перепиской.
- Текст сообщений, API-ключи и сырые ошибки SDK не выводятся в логи.

Для удаления истории конкретной группы (подставьте её числовой ID):

```bash
docker compose exec postgres sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"'
```

В открытой SQL-консоли:

```sql
DELETE FROM messages WHERE chat_id = -1001234567890;
```

Остановка: `docker compose down` (данные сохраняются). **`docker compose down -v` удаляет всю базу без возможности восстановления.**

## Локальная разработка

Нужны Node.js 22+ и Postgres. При запуске вне Docker задайте `DATABASE_URL` с адресом своей базы; порт Postgres в основном Compose намеренно не опубликован. Внутри Docker подключение задают переменные `PGHOST`, `PGUSER`, `PGPASSWORD`, `PGDATABASE` автоматически.

```bash
npm ci
npm run dev
```

Проверки:

```bash
npm run check
npm test
npm run build
```

Интеграционные проверки базы: `npm run test:integration` (укажите `DATABASE_URL` тестовой базы и непустые тестовые `TELEGRAM_BOT_TOKEN`, `OPENAI_API_KEY`; внешние API при этой проверке не вызываются). Скрипт создаёт и удаляет тестовые записи с ID групп `-987654321001` и `-987654321002` — запускайте только на отдельной тестовой базе.

CI запускает эти проверки, тесты с Postgres и сборку Docker-образа. Для проверки с настоящими Telegram и OpenAI нужны ваши ключи и оплаченный API-баланс.
